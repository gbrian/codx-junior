# CodeEngine Overview

The `CodeEngine` is a core module responsible for handling all complex code generation and improvement operations within the system. It serves as a centralized utility class that manages file modifications, patch applications, execution of bash scripts, and advanced interaction with AI models to refine project codebases.

## Initialization and Properties

### `__init__(self, session: CODXJuniorSession)`
Initializes the engine instance by requiring an active `CODXJuniorSession` object. This linkage provides access to the project context and session management functionalities throughout all operations.

### `@property settings`
Provides a convenient shortcut to access the current operational `settings` of the encompassing session.

### `@property event_manager`
Provides a convenient shortcut to access the session's `event_manager`, allowing for uniform logging and event triggering during execution steps.

## Core Code Generation and Application Methods

The engine provides several methods dedicated to different modes of code interaction: bash execution, controlled file patching, and full content regeneration.

### 🚀 `excute_bash_code(chat: Chat, code_block_info: dict)`
Executes a specified bash code block directly within the project context.

**Flow:**
1.  Switches the session's context to the active chat's project ID.
2.  Calls `exec_command` using the provided script and the project's absolute path (`self.settings.abs_project_path`) as the working directory.
3.  Logs the full execution details (stdout and stderr) into the chat history.
4.  **Error Handling:** Catches exceptions during execution, logs an error event, and re-raises the exception.

### ✍️ `generate_code(chat: Chat, code_block_info: dict)`
Determines whether a piece of generated code is intended for terminal execution (bash) or file modification/patch application.

**Logic Flow:**
1.  Switches the session context to the active project.
2.  Queries the AI by passing the code and asking if it can be executed in a terminal (`YES/NO` answer validation).
3.  **If `is_bash` is YES:** Delegates execution to `excute_bash_code()`.
4.  **If not bash (File Change):**
    *   Appends an "Apply this code" message to the chat history.
    *   Triggers `improve_existing_code()` with `apply_changes=True` to apply changes immediately.

### 🩹 `improve_existing_code(chat: Chat, apply_changes: bool = None)` (Reference: [Improve Code])
Represents the primary mechanism for improving existing code using AI-generated find & replace instructions.

**Process Details:**
1.  **Context Gathering:** Retrieves all knowledge sources and generates a markdown tree view of the entire project structure (`sources_tree`).
2.  **Prompt Construction:** Constructs a detailed request prompt, including:
    *   Project name and root path details.
    *   The structured list of best practices from the `software_developer` profile.
    *   The file system tree view.
3.  **Execution:** Uses an internal recursive helper (`try_chat_code_changes`) to chat with the AI, asking it to generate instructions in a strict format (`AI_CODE_GENERATOR_PARSER`).
4.  **Application (if `apply_changes` is True):** Calls `apply_improve_code_changes()` to commit the changes detected by the AI output.

---
*References:*
*   [Improve Code]: Methods and functionality described in `self.improve_existing_code`.

## Advanced File Manipulation Routines

### 🧱 `apply_improve_code_changes(chat: Chat, code_generator: AICodeGenerator)` (Reference: [Apply Changes])
Processes the list of changes generated by the AI to modify the actual project files.

**Workflow:**
1.  Groups all provided change instructions by their unique file path.
2.  Iterates through each file pair:
    *   **Deletion:** If `change_type` is `"delete_file"`, the file is physically removed using `os.remove()`.
    *   **Modification:** For other types, it reads the current file content and calls `change_file_with_instructions()` to ask the AI to apply all instructions at once.
3.  **Post-Processing:** If the chat context is provided, a final `git diff` command is executed against all changed files, and the result is appended to the chat history.

### 📜 `change_file_with_instructions(instruction_list: list, file_path: str, content: str)` (Reference: [File Change])
Rewrite an existing file by instructing the AI (`session.chat_with_project`) to apply a provided list of JSON-extracted instructions simultaneously.

**Input:** A list of structured changes and the current file `content`.
**Goal:** Prompts the AI with the developer profile, all stored instructions, and the full existing content, demanding that it returns *only* the clean, updated file content without any markers or explanatory text.

### 🔄 `generate_full_file_content(file_path: str, partial_content: str, original_content: str = None)` (Reference: [Full Content Generation])
Generates a complete and final version of a file when provided with only partial content from an AI segment. This is critical for maintaining structural integrity.

**Mechanism:**
1.  Reads the `original_content` if it exists on disk.
2.  Gathers comprehensive context: project-specific files profiles (if multiple apply), and default developer profiles.
3.  Constructs a detailed prompt that includes:
    *   File Path/Project Context.
    *   Gathered Profile Guidelines and Original Content.
    *   The partial content provided by the user/system.
4.  **Output Constraint:** Prompts the LLM to return the absolute full file content in a specific JSON format, ensuring proper formatting and seamless integration of generated text into the whole structure.

### 🛡️ `apply_patch(patch: str)` (Reference: [Patch Application])
Applies a standard git-style diff patch string to a specified file using multiple AI steps for maximum accuracy.

**Workflow:**
1.  Identifies the target file path from the patch header (`+++ b/`).
2.  Reads the original content of the target file.
3.  Constructs a prompt containing three major components:
    *   Developer Profile Guidelines.
    *   Original File Content.
    *   The literal Git Patch content.
4.  Requests the AI to synthesize the final, complete file content after applying both the patch and respecting professional coding standards. The output is extracted via specific JSON parsing logic.

## Utility Methods

### `project_script_test()` (Reference: [Project Test])
Executes a pre-configured command (`self.settings.script_test`) to run project tests or validation scripts directly in the terminal. It evaluates the standard output using an optional regular expression check (`self.settings.script_test_check_regex`).

### `extract_changes(content: str)`
A generator function designed to robustly parse raw text containing multiple JSON-encoded change objects, yielding individual dictionaries that contain structured change data ready for application.

### `change_file(context_documents: list, query: str, file_path: str, org_content: str, save_changes: bool = False)`
Provides a high-level API to rewrite an entire file based on external context documents and a user-defined task/query. This function encapsulates the process of writing structured prompts combining the original content, surrounding documentation, and requested changes into a single chat session with the AI for generation.
